# Sprint #5: Release Closeout, Local-First Dev & Expo SDK 58 (November 2026)

This sprint closed the gap between the server migrations deployed in Sprint #3 and the installed clients, established a local-first Supabase development environment so simulator runs and tests never mutate live data, and upgraded the project from Expo SDK 57 to Expo SDK 58 (React Native 0.88.1, React 19.3).

- **Old Client Editing an Expense No Longer Reassigns Who Paid It (`20261027120000_preserve_payers_on_update.sql`):** `update_expense_with_shares` previously treated an empty `p_payers` as "reset payers to `auth.uid()` for the full amount". Any pre-multi-payer client sends no `p_payers`, so a v1.0.0 user editing only the title of someone else's expense silently became its sole payer while `expenses.paid_by` still read the original payer. Fixed by making an empty `p_payers` on UPDATE preserve existing payer rows when the amount is unchanged, pro-rate them in integer kuruş when the amount moves (matching client-side `updateExpense` in `split-data.ts`), and fall back to `expenses.paid_by` — never `auth.uid()` — only when no payer rows exist. Covered by `supabase/tests/expense_payer_preservation_test.sql` (8 cases).
- **Equal Split Under One Kuruş Per Person & Remainder Distribution:** The equal-split branch in `split-data.ts` previously emitted zero-amount shares when `amount / n < 0.01` (e.g. `0.02 / 3` → `[0.02, 0, 0]`), which `validate_expense_allocations` rejected (`invalid_share_amount`). Extracted a shared `equalShares` helper used by both `addExpense` and `updateExpense` that computes shares in integer kuruş, spreads any remainder one kuruş at a time across the first participants (`0.02 / 3` → `[0.01, 0.01]`, `100 / 7` → four × `14.29` + three × `14.28`), and drops zero-amount rows. Also made expense list ordering deterministic (`date DESC, created_at DESC, id DESC`) in `expenses-supabase.ts` and `utils/expense.ts`.
- **iOS 27.1+ SDK Launch Crash (`UIScene` Lifecycle):** Binaries built with the iOS 27.1+ SDK without a `UIApplicationSceneManifest` trap at launch in `_UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption`. Initially resolved on SDK 57 via `expo-build-properties` (`ios.enableSceneSupport: true`, verified on Simulator; Build 14 was rejected at upload and Build 15 was not tested on a device, so the first iOS 27.2 device check is TestFlight Build 16), then superseded by Expo SDK 58's native `SceneDelegate.swift` (`ExpoAppSceneDelegate`) template.
