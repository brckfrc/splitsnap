# Sprint #13: Test Harness & CI (November 2026)

Pulled forward ahead of Sprint #6 on 2026-11-22. Before it, a Renovate PR got no automated verification, the SQL suites printed FAIL but exited 0, and there was no unit test runner or CI. After it, every PR (Renovate's included) runs the Expo pin check, typecheck, lint, unit tests and the SQL suites, and the money paths have tests that have already caught two real bugs. The same checks are steps 1–3 of the pre-release gate in [`docs/APP-STORE.md`](../APP-STORE.md), which every production build now passes first.

- **SDK 58 Alignment (`PR #28`), Replacing Renovate #26:** #26 moved packages Expo SDK 58 pins (`react`/`react-dom` 19.3.1, reanimated 4.7.2, worklets 0.13.1, gesture-handler 3.5, datetimepicker 9.3.0) off the SDK's `bundledNativeModules` set, so it was closed. The alignment went through `npx expo install expo@58.0.26` + `--fix`, plus supabase-js 2.119.1, zustand 5.1.0, tamagui 2.7.7 (single `@tamagui/portal` copy confirmed) and Node 26.13.1. The full gate including a simulator pass found and fixed a pre-existing bug: the iOS date spinner's text stayed black on the dark sheet because `DatePickerModal` did not pass the app theme (`themeVariant`/`textColor`).
- **SQL Suites That Can Fail (`npm run test:db`):** [`scripts/test-db.sh`](../../scripts/test-db.sh) runs `supabase/tests/*.sql` and exits non-zero on any `FAIL`/`ERROR` line, a psql error, or a suite that prints no `PASS`; proven against a failing, an empty and an erroring suite. A third suite, `groups_settlements_receipts_test.sql`, characterises invite codes, settlement RLS and receipt storage paths (24 cases; 51 in total).
- **Jest Unit Tests (`npm test`):** `jest-expo` (SDK-pinned) with `@react-native/jest-preset` 0.88.1; 33 tests over `settlement` (balances sum to zero, paying the suggestions zeroes the group, multi-payer and multi-creditor cases), `numeric`, `validation` and `invite`.
  - **`amountsMatch` one-kuruş boundary:** the float compare accepted a one-kuruş gap at ₺10 and rejected it at ₺100 (`100.01 - 100` is 0.010000000000005); now compared in whole kuruş, like the server's exact `numeric`.
  - **`parseAmount` thousands separators:** a pasted "1.234,56" saved as ₺1,23 with no error. It now reads Turkish and English notation and returns NaN for ambiguous input; the ~20 inline `parseFloat(x.replace(',', '.'))` copies in `add-expense.tsx`/`edit.tsx` call it, so totals, shares and payer amounts parse alike.
- **GitHub Actions CI (`.github/workflows/ci.yml`):** two jobs on every PR and on pushes to `main`/`dev` — `npm ci` → `expo install --check` → `check` → `npm test`, and `supabase db start` → `test:db`. Actions on current majors (checkout v7, setup-node v7, setup-cli v3); about one minute per job.
- **Renovate Rules (`renovate.json`):** SDK-pinned packages are disabled (they move with `expo install --fix` or an SDK upgrade), MMKV + Nitro wait for Dependency Dashboard approval as one group, and `design/figma_template` updates go to a separate monthly group. #27 rebased itself down to supabase-js 2.119.2 (lockfile only) and was CI's first green Renovate run.
- **Maestro Smoke Flow (`npm run test:e2e`, local only):** [`.maestro/smoke.yaml`](../../.maestro/smoke.yaml) signs in as Deniz, adds a ₺300 equal-split expense, checks the settlement screen (total ₺4.800, Deniz ₺3.200), records a suggested payment and checks that one debtor remains — about 1 min 40 s, stable across repeated runs. [`scripts/test-e2e.sh`](../../scripts/test-e2e.sh) resets the local database first and takes the password from `SMOKE_PASSWORD`. Subflows handle what a cleared-state dev build shows on iOS 27 (the "Open in SplitSnap?" prompt, the dev menu intro and menu, the Save Password sheet). The login fields gained `testID`s, since iOS hides a secure field's placeholder. Running it in CI (macOS runner + an iOS build per PR) is in the Backlog.

## Follow-ups (2026-11-22, after the sprint closed)

- **One-button release (`PR #31`):** `.github/workflows/release.yml` (manual, on `main`) runs CI, rebuilds the hosted `splitsnap-staging` Supabase project from migrations + seed (`scripts/staging-reset.sh`, refuses production by ref and by name), builds an unsigned EAS `e2e` simulator build against staging, runs the Maestro smoke flow on a GitHub macOS runner, then builds for production on EAS and uploads to TestFlight. GitHub Actions orchestrates because Expo's Free plan has no Maestro jobs; GitHub's macOS runners are free for this public repo. `staging-keepalive.yml` stops the free-plan pause. The staging project's rationale, and why it had been deferred on 2026-11-03, is in the ROADMAP Backlog.
- **`dev` branch retired:** every change is a feature branch from `main` → PR → `main`. With required CI on `main` and a release that cannot skip its tests, `dev` only lagged behind and needed manual syncing.
- **Renovate auto-merge:** lockfile maintenance and patch/pin/digest updates merge themselves once the required CI is green; minor updates and Tamagui (UI the CI cannot see) stay manual.
- **Release tags:** a successful production run tags its commit `v<version>-build.<n>`.
